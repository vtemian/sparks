# Docker-py Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace every production `subprocess` call to the Docker CLI with the Docker SDK for Python (`docker`), while keeping SSH/rsync as subprocess and preserving supervise-outside-container abort/energy semantics.

**Architecture:** Add `docker` as a runtime dependency. Laptop `build`/`push` and queue `pull`/`rm` talk to the daemon via `docker.from_env()`. The nested `docker run` under supervise becomes `python -m sparks.fire.contain …` — a thin SDK driver that create/start/waits the training container, writes the cidfile, streams logs to stdout (supervise tees them), and maps SIGTERM→`container.stop` so abort still records `cancelled`. The static Docker CLI binary is removed from the queue image once nothing shells out to it.

**Tech Stack:** Python 3.12, PyPI `docker` (import `docker`), pytest, existing `sparks.fire.supervise` / `process.Supervisor`, unix socket `/var/run/docker.sock`.

## Global Constraints

- Keep the mental model: supervise stays **outside** the training image; projects do not add sparks as their entrypoint.
- Abort path must still SIGTERM the supervise child tree and record `cancelled`, not silent `finished`. Do **not** kill the training container behind supervise’s back from `Process.terminate`.
- Security boundary stays in the queue: the job file may name only `image` + `command`. Mounts, user, gpus, network aliases are chosen by fire code and must remain unit-tested as a pure argv/spec builder.
- Empty `gpus=""` must omit GPU requests (laptop / no-nvidia-runtime boxes).
- `host.docker.internal:host-gateway` must keep working for Prometheus from inside the training container.
- SSH, rsync, and git stay subprocess. Only Docker Engine operations move to the SDK.
- Preserve public error shapes: laptop `ClientError` messages (incl. insecure-registries hint); queue `PullFailed` with `pull.log`.
- Pull timeout remains 1h (`PULL_TIMEOUT_SECONDS`); cleanup remains best-effort and never raises into the runner.
- No new auth, no HTTP control plane, no third console script.

## Decision log (locked for this plan)

1. **One dependency for laptop and queue.** Same PyPI package; laptop uses host Docker Desktop/daemon, queue uses mounted sock.
2. **Keep supervise nesting; replace only the inner CLI.** Do not fold docker-py into `supervise.py` or rewrite `process.Supervisor`. Child becomes the contain module.
3. **No `--cidfile` / no `--rm` races.** Contain writes `container.id` after create; wait/logs with `auto_remove=False`; explicit `remove(force=True, v=True)` in contain’s `finally` and keep engine `finish`/`release` as best-effort sweep.
4. **`--gpus all` → `DeviceRequest(count=-1, capabilities=[["gpu"]])`.** Specific device lists are out of scope unless `gpus` already supports them (today it is `"all"` or `""` only).
5. **Remove the static CLI from the image** in the same change set that deletes the last `docker` argv. Keep `docker_group()` via `stat()` on the sock — contain still runs as the submitter and needs the socket gid.

```python
"""Talk to a Docker daemon without shelling out to the CLI."""

from __future__ import annotations

import logging

import docker
from docker.errors import APIError, DockerException, NotFound

LOG = logging.getLogger("sparks")

__all__ = ["APIError", "DockerException", "NotFound", "client", "remove_quietly"]


def client() -> docker.DockerClient:
    return docker.from_env()


def remove_quietly(
    docker_client: docker.DockerClient,
    container_id: str,
    *,
    timeout: float = 60.0,
) -> None:
    """Best-effort force-remove; never raises to the runner."""
    try:
        container = docker_client.containers.get(container_id)
        container.remove(force=True, v=True)
    except NotFound:
        return
    except (APIError, DockerException, OSError) as e:
        LOG.warning("sparks: docker remove %s failed: %s", container_id[:12], e)
```

(If `timeout` cannot be threaded into the SDK call cleanly, keep the parameter for API parity with today’s `CLEANUP_TIMEOUT_SECONDS` and document that the SDK call is unbounded but failures are swallowed — do **not** reintroduce a CLI timeout wrapper.)

```python
def build(context: Path, tag: str) -> None:
    if not (context / "Dockerfile").is_file():
        raise ClientError(f"{context}/Dockerfile is missing")
    try:
        client = dock.client()
        # Low-level API streams chunks as they arrive.
        stream = client.api.build(
            path=str(context),
            tag=tag,
            decode=True,
            rm=True,
        )
        for chunk in stream:
            if "stream" in chunk:
                print(chunk["stream"], end="")
            if "error" in chunk or "errorDetail" in chunk:
                raise ClientError(f"docker build failed for {tag}")
    except dock.DockerException as e:
        raise ClientError(f"docker build failed for {tag}: {e}") from e


def push(tag: str) -> None:
    # Split name:tag for images.push; tag may contain registry host:port.
    if ":" not in tag.rsplit("/", 1)[-1]:
        repository, image_tag = tag, "latest"
    else:
        repository, image_tag = tag.rsplit(":", 1)
    try:
        client = dock.client()
        for line in client.images.push(
            repository, tag=image_tag, stream=True, decode=True
        ):
            if line.get("error") or line.get("errorDetail"):
                raise ClientError(
                    f"docker push failed for {tag}. Is the registry in "
                    f"insecure-registries and is SPARKS_HOST reachable?"
                )
            # Optional: print status lines for parity with CLI progress.
            status = line.get("status")
            if status:
                print(status)
    except ClientError:
        raise
    except dock.DockerException as e:
        raise ClientError(
            f"docker push failed for {tag}. Is the registry in "
            f"insecure-registries and is SPARKS_HOST reachable?"
        ) from e
```

Wrap missing daemon / socket errors into `ClientError` (same user-facing class as today). Do not leave bare `FileNotFoundError` for a missing CLI — that failure mode goes away.

Write progress / error text into `log_path` (bytes or text — match existing `wb` usage). Use streaming pull with a wall-clock timeout:

```python
def pull(self, image: str, log_path: Path) -> None:
    import time

    deadline = time.monotonic() + PULL_TIMEOUT_SECONDS
    try:
        client = dock.client()
        with log_path.open("wb") as log:
            for chunk in client.api.pull(image, stream=True, decode=True):
                if time.monotonic() > deadline:
                    raise PullFailed(
                        f"the pull was still going after "
                        f"{PULL_TIMEOUT_SECONDS / 3600:g}h and was stopped"
                    )
                line = (chunk.get("status") or chunk.get("error") or str(chunk))
                log.write((line + "\n").encode())
                if chunk.get("error") or chunk.get("errorDetail"):
                    raise PullFailed(
                        f"docker pull failed; the output is in {log_path.name}"
                    )
    except PullFailed:
        raise
    except dock.DockerException as e:
        raise PullFailed(f"could not pull image: {e}") from e
```

### Task 4: `sparks.fire.contain` — SDK child under supervise

**Files:**
- Create: `src/sparks/fire/contain.py`
- Create: `tests/test_contain.py`

**Interfaces:**
- Consumes: `dock.client`, `docker.types.DeviceRequest`, argv flags from engine
- Produces:
  - CLI module: `python -m sparks.fire.contain --name … --cidfile … [--gpus all] --user U:G --shared-dir … --data-dir … --workdir … IMAGE -- CMD…`
  - Exit code = training container `StatusCode` (clamped like today via supervise/process, not contain)
  - On SIGTERM/SIGINT: `container.stop(timeout=…)` then wait; exit non-zero so supervise records cancel path when the child dies to signal — **match current docker CLI behavior**: supervise forwards signals to the child process group; contain must stop the container when signalled and then exit so the wrapper sees cancelled/killed honestly

**Signal contract (critical):**

Today: supervise → SIGTERM → `docker run` CLI → container PID 1 (with `--init`).

After: supervise → SIGTERM → contain process → `container.stop(timeout=GRACE)` (or `kill`) → wait → exit.

Contain must install signal handlers (or rely on supervise’s forwarding into a process that calls stop in a `finally` after a flag). Prefer an explicit handler that sets a flag and calls `stop`, then exits with a non-zero code if aborted.

Use `init=True` on create/run for the same PID 1 reason as `--init`.

Sketch:

```python
"""Create and wait on one training container via the Docker SDK.

Invoked as the child of `python -m sparks.fire.supervise -- …` so energy
sampling and cancel semantics stay outside the project's image.
"""

def run_kwargs(...) -> dict: ...  # pure; unit-tested

def main(argv: list[str] | None = None) -> int:
    args = parse(argv)
    client = dock.client()
    container = None
    aborted = False

    def on_signal(signum, frame):
        nonlocal aborted
        aborted = True
        if container is not None:
            with contextlib.suppress(Exception):
                container.stop(timeout=int(process.GRACE_SECONDS))

    signal.signal(signal.SIGTERM, on_signal)
    signal.signal(signal.SIGINT, on_signal)

    try:
        container = client.containers.run(
            **run_kwargs(...),
            # volumes: shared bind + data_dir -> /data:ro
        )
        Path(args.cidfile).write_text(container.id + "\n", encoding="utf-8")
        for chunk in container.logs(stream=True, follow=True, stdout=True, stderr=True):
            sys.stdout.buffer.write(chunk)
            sys.stdout.buffer.flush()
        code = container.wait()["StatusCode"]
        if aborted:
            return 1  # non-zero; supervise/process classify via signals when possible
        return int(code)
    finally:
        if container is not None:
            with contextlib.suppress(Exception):
                container.remove(force=True, v=True)
```

Forward env: `SPARKS_RUN_ID` and `SPARKS_PROMETHEUS_URL` must be taken from **contain’s environment** (supervise sets them) the same way CLI `--env NAME` without value did.

## Out of scope

- Replacing ssh/rsync/git subprocesses
- BuildKit / `docker buildx` features beyond classic `api.build`
- Per-device GPU scheduling beyond `all` / omit
- HTTP image upload instead of registry push
- Changing sparkup sock mounts or compose service shape (beyond image contents)
- Migrating `tests/promtool.py` / harness scripts off the Docker CLI

## Rollback

Revert the branch/commits; queue image with static CLI + old engine still works. Do not mix a new client (SDK build/push) with an old fire image that still expects only CLI if contain module is missing — deploy fire image before relying on contain argv from a new engine (same image build ships both).
